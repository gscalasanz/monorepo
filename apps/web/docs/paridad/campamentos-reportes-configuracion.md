## campamentos

- Rutas (`/campamentos`, título "Campamentos" / "Planifica y gestiona los campamentos del grupo"): `''` lista, `crear` form, `:id` detalle, `:id/editar` form (edición).
- **Lista** (`GET /campamentos`, backend ordena `fechaInicio DESC`, trae `participantes.persona`): spinner mientras carga; error sin datos → ícono + mensaje (fallback "Error al cargar campamentos"); error con datos → se sigue mostrando.
- Vacío: "No hay campamentos registrados" / "Comienza creando tu primer campamento para gestionar participantes y pagos." + botón "Crear Campamento".
- Barra de stats ("Resumen de campamentos"): total "Campamentos" + "Próximos" / "En curso" / "Finalizados" + botón "Crear Campamento". Cálculo cliente: hoy(00:00) < inicio → próximo; inicio ≤ hoy ≤ fin(23:59:59.999) → en curso; si no finalizado.
- Card: badge estado: próximo con "{N}d" (N = ceil((inicio−ahora)/día), solo si N>0), "En curso", "Finalizado" (un próximo con N≤0 cae en "Finalizado"). Nombre, fechas `d MMM — d MMM`, stats "Participantes" (`participantes.length`), "Costo" (`costoPorPersona` money), "Cuotas" (`cuotasBase ?? 1`), descripción si existe.
- Acciones card: click/"Ver detalle" → detalle; editar → `/:id/editar`; eliminar → confirmDelete('campamento') → `DELETE /campamentos/:id` → se quita de la lista + toast "Campamento eliminado exitosamente". 400 "No se puede eliminar: el campamento tiene N movimiento(s) asociado(s)" → toast global.
- Errores: toast global con `message` de NestJS (array unido con ". "), fallback por status.
- **Form**: título "{Nuevo|Editar} Campamento", subtítulo "Registra un nuevo campamento" / "Modifica los datos del campamento"; edición carga `GET /campamentos/:id` ("Cargando datos...").
  - `nombre` req, min 3, max 100, safeText, placeholder "Ej: Campamento de Verano 2024"; error único "El nombre es requerido".
  - `fechaInicio`/`fechaFin` req ("La fecha de inicio es requerida" / "La fecha de fin es requerida"); rango inválido si inicio > fin (mismo día OK) → solo deshabilita submit.
  - `costoPorPersona` req, >0, 2 decimales, prefijo `$`; error "El costo es requerido".
  - `cuotasBase` ("Cantidad de Cuotas") req, default 1, 1..12; error "Las cuotas deben ser entre 1 y 12".
  - `costoEducadores` ("Aporte de Educadores") req, default 0, ≥0, 2 dec; error "El aporte de educadores no puede ser negativo"; hint "$0 = los educadores quedan exentos y no se les registran pagos ni bonificaciones. Si ponés un monto, cada educador que no aporte consume ese monto del fondo solidario al bonificarlo — dejalo en 0 salvo que se espere cobrarles."
  - `descripcion` textarea opcional, max 500, safeText, placeholder "Descripción del campamento (opcional)"; vacío → `undefined`.
  - Botones: "Cancelar" (→ detalle en edición / lista en alta), submit "Crear Campamento" | "Actualizar" (deshabilitado si inválido, loading). Body `{nombre, fechaInicio, fechaFin, costoPorPersona, costoEducadores, cuotasBase, descripcion?}`.
  - Alta `POST /campamentos` → toast "Campamento creado exitosamente" → `/campamentos/{id}`. Edición `PATCH /campamentos/:id` → "Campamento actualizado exitosamente" → detalle.
  - Regla: `montoAsignado` del participante es snapshot al inscribirlo (`costoEducadores` si educador, si no `costoPorPersona`); editar costos no recalcula.
- **Detalle** (`GET /campamentos/:id/detalle?filtroMovimientos=todos|ingresos|egresos|gastos&nombre=&rama=`): primera carga "Cargando campamento..."; error sin datos → mensaje + "Volver"; sin datos → "Campamento no encontrado" + "Volver al listado".
  - Header: nombre, fechas `d MMM — d MMM yyyy`, countdown "{N} días" si N>0, "Volver" → lista, editar.
  - Info: descripción, "Costo por persona", "Cuotas sugeridas", "Participantes" (`kpis.cantidadParticipantes`).
  - KPIs money: "Total a Recaudar", "Recaudado", "Gastado", "Reembolsos Pendientes", "Balance". Barra "Recaudación" = min(recaudado/aRecaudar·100, 100) redondeado + "%" (0 si aRecaudar=0). KPIs del backend ignoran filtros.
  - Tabs "Participantes" / "Movimientos"; botón contextual "Agregar" / "Gasto". Footer "Eliminar" + "Editar campamento". **Rareza**: "Eliminar" del detalle solo confirma y navega a la lista sin llamar DELETE → en React se replica la intención (confirmar + `DELETE` + navegar) — ver MIGRATION §Bloqueos/desvíos.
  - Filtros participantes (auto-apply): "Nombre" ("Buscar por nombre...", ignora 1–2 caracteres, debounce 300ms) y "Rama" (Educadores, Manada, Unidad, Caminantes, Rovers). Refrescando "Buscando participantes...". Sin resultados con filtro: "Sin resultados" / "No hay participantes que coincidan con los filtros"; sin participantes: "Sin participantes" / "Agregá participantes al campamento". **Rareza**: rama `educador` → 400 en backend (IsEnum Rama).
  - Card participante: nombre; progreso `(totalPagado + montoBonificado) / montoAsignado`; "Bonificado: $X" si no exento y >0; "Inscripto el dd/MM/yyyy". Estado: `exento` → "Exento"; saldoPendiente 0 → "Al día"; si no "$saldo pendiente".
  - Toggle autorización ("Autorización entregada"/"Autorización pendiente"): `PATCH /campamentos/:id/participantes/:personaId {autorizacionEntregada}` → "Autorización actualizada exitosamente".
  - Quitar participante: confirmDelete título `Eliminar participante "{nombre}"` → `DELETE /campamentos/:id/participantes/:personaId` → "Participante removido exitosamente". Errores 400 "No se puede desinscribir: el participante tiene N pago(s) registrado(s) en este campamento", 404 "El participante no está inscrito en el campamento".
  - Historial en la card (`pagos`): fecha `d/M`, monto ("-" si egreso), label concepto ("Pago de Campamento" / "Bonificación Otorgada" / "Bonificación Recibida"), medio. Lápiz "Editar pago" solo si `campamento_pago`.
  - Botones card: "Registrar pago" (si saldo>0), "Bonificar"/"Ajustar bonificación" (no exento), "Quitar bonificación" (si bonificado>0, sin confirmación: `DELETE …/participantes/:personaId/bonificacion` → "Bonificación removida exitosamente").
- **Agregar participante**: "Agregar Participante" / "Seleccioná una persona para inscribir al campamento". `GET /personas?soloActivos=true`, cliente filtra protagonistas y educadores no inscriptos. Select "Filtrar por Rama" (opcional, "Todas las ramas", resetea persona). Persona req ("Seleccione una persona", "No hay personas disponibles", "{n} persona(s) disponible(s)"). Checkbox "Autorización entregada". "Bonificar (opcional)" si max>0 (max = costoEducadores o costoPorPersona; "Máximo: $max" / "No puede exceder $max"). "Registrar pago (opcional)" max = max − bonificado; si >0 "Medio de pago" (Efectivo/Transferencia). Encadena: `POST /campamentos/:id/participantes {personaId, autorizacionEntregada?}` ("Participante agregado exitosamente"; 400 "Esta persona ya está inscrita en el campamento") → PATCH bonificación → POST pago; si un paso falla se corta.
- **Registrar pago**: antes `GET /cajas/personal/:personaId/saldo` → `{saldo}`. Resumen "Costo por persona:" (asignado − bonificado), "Total Pagado:", "Saldo Pendiente:", "Saldo Cuenta Personal:" (si >0), barra "{p}% completado". Campos: "Usar Saldo Personal" (si saldo>0, "Disponible: $X", "No puede exceder el saldo disponible"); monto ("Monto en Efectivo/Transferencia" o "Monto del Pago"); "Medio de Pago" si monto>0 ("Seleccione un medio de pago"); "Descripción" ("Notas adicionales..."). "Desglose del Pago:" si mixto; "Saldo Restante:". Rápidos: "Pagar Todo (mixto)", "Solo Saldo ($…)", "Solo Efectivo ($pendiente)". Submit deshabilitado si total ≤ 0, total > pendiente, monto sin medio o saldo usado > disponible. `POST /campamentos/:id/pagos/:personaId {montoPagado, montoConSaldoPersonal?, medioPago?, descripcion?}` → "Pago registrado exitosamente".
- **Editar pago**: el endpoint `PATCH /campamentos/:id/pagos/:movimientoId` **no existe** en el backend (Angular siempre da 404). Eliminar pago sí: `DELETE /campamentos/:id/pagos/:movimientoId` → "Pago eliminado exitosamente".
- **Bonificar**: `GET /cajas/fondo-solidario` → `{caja|null}` (saldo = `caja.saldoActual`). Muestra "Monto asignado:", "Ya pagado:", "Saldo Fondo Solidario:". "Monto a Bonificar" (default = actual, hint "Máximo bonificable: $X" con X = max(0, asignado − pagado); errores "No puede exceder el saldo pendiente ($X)" y "El fondo solidario no tiene saldo suficiente" comparando el adicional). Rápido "Bonificar el saldo pendiente ($X)". 0 → DELETE bonificación; >0 → `PATCH …/bonificacion {monto}` (TOTAL deseado) → "Bonificación actualizada exitosamente".
- **Tab Movimientos**: filtros "Todos/Ingresos/Egresos/Gastos" (recarga con `filtroMovimientos`). Card: flecha, fecha `d MMM yyyy`, descripción o "Sin descripción", responsable, monto ±, medio ("Efectivo", "Transferencia", "Saldo Personal", "Mixto"), badge "Pagado" / "Pendiente de Reembolso" / "A cobrar". Vacío "Sin movimientos" / "No hay movimientos para el filtro seleccionado". Badge "Pendiente de Reembolso" → confirm "Confirmar pago de reembolso" / "¿Confirmás que este gasto fue reembolsado?" (detalles Monto/Descripción/Responsable, botón "Pagar") → `PATCH /movimientos/:id {estadoPago:'pagado'}`.
- **Registrar Gasto**: `GET /personas?soloActivos=true`. "Monto" (req, >0; "El monto es requerido"/"Debe ser un número positivo"), "Fecha" (req, default hoy; "La fecha es requerida"), "Responsable" (req; "Seleccione un responsable"), "Descripción" (req, max 500; "La descripción es requerida"/"Máximo 500 caracteres"; "Ej: Compra de alimentos, transporte, etc."), "Medio de Pago" (Efectivo/Transferencia), "Estado de Pago" (Pagado / Pendiente de Reembolso). Pendiente → banner "Este gasto no descuenta del saldo de la caja. Se registra como pendiente de reembolso para la persona seleccionada." + "Persona a Reembolsar" req ("Seleccione la persona que adelantó el dinero"). `POST /campamentos/:id/gastos {monto, descripcion, responsableId, medioPago, estadoPago, fecha?, personaAReembolsarId?}` → "Gasto registrado exitosamente".
- Deuda de campamento: el front usa `saldoPendiente` del backend (= max(0, asignado − pagado − bonificado)).
- Rareza: tras acciones Angular recarga el detalle SIN filtros; en React se recarga con los filtros vigentes (mejora de consistencia, sin cambio de regla).
- Rareza: fechas `YYYY-MM-DD` parseadas como UTC en Angular (día anterior en AR); React usa `@/shared/time`.

## reportes

- Rutas (`/reportes`, oculto del sidebar): `''` → `deudas`; `reembolsos`, `caja`, `eventos`, `comprobantes` son placeholders sin API ("Reporte de Reembolsos Pendientes" / "Reporte de reembolsos pendientes", "Reporte de Caja" / "Reporte de movimientos de caja", "Reporte de Eventos" / "Reporte de resultados de eventos", "Reporte de Comprobantes Pendientes" / "Reporte de comprobantes pendientes").
- **Deudas**: `GET /reportes/deudas?rama=&ano=&tipo=` (público), recarga al cambiar un filtro.
- Filtros: "Rama" ("Todas las ramas": Manada, Unidad, Caminantes, Rovers, Educadores), "Año" ("Todos los años", año actual hacia atrás hasta 2020), "Tipo de deuda" ("Todos los tipos", "Dinero (todas)"=dinero, Campamentos=campamentos, "Inscripciones Scout AR"=inscripcionesScout, "Inscripciones Grupo"=inscripcionesGrupo, Documentación=documentacion), botón limpiar.
- KPIs: "Personas con deuda", "Deuda total" (rojo), "Con docs faltantes".
- Estados: "Cargando reporte..."; error "Error al cargar el reporte. Verifique su conexión e intente nuevamente." + "Reintentar"; vacío "No hay deudas pendientes con los filtros seleccionados".
- Tabla: "Nombre" (link a la ficha según tipo, aria "Ver ficha de {nombre}"), "Rama", "Deudas" (chips "{label} {año} {$saldo}" con labels "Camp."/"Scout AR"/"Grupo", solo saldo>0, orden año asc y label; chip "{n} docs" si faltan), "Total". Orden del backend.
- Fila expandible (una a la vez): "Deudas monetarias" (cards label, año, nombre, saldo), "Autorizaciones faltantes" ("Aut. {camp} {año}"), "Documentación": personales "DNI", "Partida nac.", "DNI padres" (omitido si mayor), "Obra social"; por inscripción "Decl. salud {año}", "Aut. imagen {año}", "Salidas {año}", "Aut. ingreso {año}", "Apt. física {año}".
- countDocsFaltantes = personales false + campos false por inscripción + campamentos sin autorización.

## configuracion

- Card "Mi Perfil" (ver auth en MIGRATION.md), luego "Backup y Exportación": "Descargá un respaldo de tus datos. Elegí el formato según lo que necesites."
- "Exportar a Excel" ("Archivo .xlsx con una hoja por tabla para abrir en Excel o Google Sheets"): `GET /exports/xlsx` blob; "Descargando..." deshabilitado; éxito "Exportación descargada"; error "Error al exportar a Excel".
- "Backup de base de datos" ("Archivo .sql.gz restaurable en PostgreSQL para recuperar los datos"): `GET /backups/download`; éxito "Backup descargado"; error "Error al generar el backup".
- Descarga: body vacío → error; filename de `Content-Disposition` con `/filename="?([^";]+)"?/`, fallback `scout-export.xlsx` / `scout-backup.sql.gz`; ObjectURL + `<a download>` + revoke.
- "Configuración de Inscripciones": "Monto Inscripción Scout Argentina", "Monto Inscripción de Grupo" (≥0), "Guardar" → inválido "Por favor, ingrese valores válidos"; ok "Configuración guardada exitosamente". Solo localStorage `scout_inscripcion_config` (ya en `@/shared/settings`).

## Contratos

- `GET /campamentos` → entidad con decimales string, fechas `YYYY-MM-DD`, `participantes: {id, campamentoId, personaId, autorizacionEntregada, montoAsignado, montoBonificado, persona}[]`.
- `GET /campamentos/:id/detalle` → `{ campamento: {id, nombre, fechaInicio, fechaFin, costoPorPersona, costoEducadores, cuotasBase, descripcion|null}, participantes: {id(personaId), nombre, tipo, rama|null, montoAsignado, montoBonificado, totalPagado, saldoPendiente, estadoPago: pendiente|parcial|pagado|exento, autorizacionEntregada, fechaInscripcion, pagos: {movimientoId, fecha, monto, medioPago, tipo, concepto}[]}[], movimientos: {id, fecha, tipo, concepto, monto, descripcion|null, medioPago, estadoPago, responsableId, responsableNombre}[], kpis: {totalARecaudar, totalRecaudado, totalBonificado, totalGastado, totalPendienteReembolso, balance, deudaTotal, cantidadParticipantes, …} }`.
- `POST /campamentos/:id/pagos/:personaId` → `{movimientoIngreso, movimientoEgresoPersonal?, desglose}`; `DELETE …/pagos/:movimientoId` → `{movimientosEliminados, montoRevertido}`.
- `GET /cajas/personal/:personaId/saldo` → `{saldo}`; `GET /cajas/fondo-solidario` → `{caja: (Caja & {saldoActual}) | null}`.
- `GET /reportes/deudas` → `PersonaDeuda[]` `{personaId, nombre, tipo, estado, rama, esMayorDeEdad, deudaTotal, campamentos[], inscripcionesGrupo[], inscripcionesScout[], documentacionPersonal|null, documentacionInscripcion[]}`.
- `GET /backups/download`, `GET /exports/xlsx` → binario con `Content-Disposition`.
